# 가비지 컬렉션(Garbage Collection)
## 가비지 컬렉션의 목적과 필요성
> 가비지 컬렉션: 컴퓨터의 환경 미화원
- 더 이상 사용하지 않는 메모리 영역을 자동으로 찾아 회수
- 메모리 누수를 방지
  1. 메모리 누수? 상요 끝난 메모리를 반환하지 않고 계속 점유하는 것
  2. 메모리 누수의 문제점?
     - 컴퓨터의 물리적 RAM 용량의 한계로 가상 메모리의 한계 존재
     - 메모리 자원 고갈, 컴퓨터 속도 저하 (CPU가 데이터를 읽고 쓰는 공간이 RAM)
  3. 개발자가 수동으로 메모리 관리에 대한 신경 X

> 더 이상 사용하지 않는 변수나 객체는 메모리에서 언제 사라지는가?
- 가비지 컬렉션 기반 언어 (JAVA 등)
  1. 객체가 더 이상 어떤 변수 와도 연결되지 않을 때
  2. 방법: 가비지 컬렉션이 주기적으로 실행, 참조 X -> 메모리에서 제거
  3. 주의: 코드 구성 방법에 따라 필요하지 않은 메모리 할당이 제거가 안 될 수 있음
- 가비지 컬렉션 비기반 언어 (C/C++ 등)
  1. 개발자가 free() 등의 함수를 호출하여 명시적으로 해제를 요청하는 경우


## Heap, Stack, Method Area
- 객체 Heap 영역에서 생성되고 Method Area이나 Stack Area 에서는 Heap Area에 생성된 객체의 주소만 참조하는 형식으로 구성

- Heap Area의 객체들이 메서드가 끝나는 등의 특정 이벤트들로 인하여 Heap Area 객체의 메모리 주소를 가지고 있는 참조 변수가 삭제되는 현상이 발생

- 참조하고 있지 않은 객체(Unreachable)들이 발생
  1. ex) return 값
 
## Mark-and-sweep
- Mark 과정 : 먼저 Root Space로부터 그래프 순회를 통해 연결된 객체들을 찾아내어 각각 어떤 객체를 참조하고 있는지 찾아서 마킹
  1. Root space: 객체들의 시작점 역할을 하는 객체들의 집 
- Sweep 과정: 참조하고 있지 않은 객체 즉 Unreachable 객체들을 Heap에서 제거

## 파이썬의 레퍼런스 카운트와 가비지 컬렉션
> 레퍼런스 카운드
- 객체가 다른 객체나 변수에 의해 참조된 수
- 객체가 생성될 경우 1

> 레퍼런스 카운트가 0?
- 메모리에서 자동으로 삭제
- 삭제된 객체의 메모리 공간은 다른 객체 등을 위해 재활용 


## 세대별 관리를 통한 가비지 컬렉션의 맞춤형 서비스
> 세대별 수집: 객체를 생성된 시점(세대)에 따라서 0, 1, 2 세대 등으로 나누어 관리
  1. 0세대: 새로 생성된 객체가 위치
  2. 1, 2세대: 이전 세대에서 살아남은 객체
- 0 세대는 짧은 주기로 레퍼런스 카운트 검사 시행
- 세대가 클수록 검사 주기가 길어짐
  -> 오래 살아남았다는 것은 진짜 필요하다는 증거!!!

> 가비지 컬렉션의 주기
- 특정 규칙 X, 메모리 사용 패턴 등에 따라 동적으로 결정
- JAVA는 튜닝을 통해 주기를 최적화하기도 

## 헷갈림 주의: 가비지 컬렉션 vs. del

|내용|가비지|del|
|----|----------|------|
|메모리 존재 유무|X|O|
|목적|메모리에서 해당 내용을 제거|객체 참조 제거|

- 참조를 제거하면, 레퍼런스 카운트가 0이니까 가비지 컬렉션으로 제거되는거 아니야?
-> 아닙니다. 포인터 등으로 다른 변수가 해당 메모리의 내용을 참조할 수 있음 (순환 참조)

## 가비지 컬렉션의 최고의 적: 순환 참조
> 두 개 이상의 객체, 모듈, 셀 등이 서로를 직접 또는 간접적으로 가리키며 꼬리를 무는 참조 구조
- 문제점: 가비지 컬렉션 작동이 불가능, 코드 이해 및 유지 보수 어려움, 메모리 누수
- 예시(엑셀): 셀 A1 이 셀 B1을 참고하는 경우 = "B1*2"

- 방법: 객체 그룹이 실제 프로그램의 다른 부분에서 도달 불가능한 '가비지'인지 확인



## 추가로 공부하기1. 참조의 종류: 강한 참조, soft 참조, 약한 참조
> 강한 참조
- 가비지 컬렉션의 대상에서 제외

> soft 참조
- 메모리 여유에 따라 다름
  1. 메모리 부족 임박: 삭제
  2. 메모리 여유: 유지

> 약한 참조
- 가지 컬렉션에서 무조건 수거
